# TapTap

Swift 原生 macOS 菜单栏工具：可配置两指、三指 × 轻触、按下 × 单击、双击，共八种组合，关闭最前面的窗口。默认启用三指双击。支持内置触控板和 Magic Trackpad；macOS 13 及以上，无第三方依赖。

## 构建与运行

需要 Xcode 或 Command Line Tools（Swift 5.9+）。

```sh
./scripts/build.sh
open dist/TapTap.app
```

建议将 `dist/TapTap.app` 拖到“应用程序”目录，再从该目录打开并授权，避免移动路径后需要重新授权。通过菜单“授权辅助功能…”打开系统设置，将 TapTap 打开；如果监听启动提示需要输入监控，再使用菜单“授权输入监控…”。程序不在启动时自动弹出授权页面。菜单显示“正在监听”后即可使用。程序只显示菜单栏图标，不显示 Dock 图标。菜单可暂停、退出，以及通过系统登录项选择开机启动（默认关闭）。

## 手势设置

点击菜单栏图标 → **设置…**，分别配置以下八个组合，每项支持“不执行”、“关闭当前窗口”或“关闭标签页或窗口（⌘W）”：

| 手势 | 默认动作 |
| --- | --- |
| 两指 · 轻触 · 单击 / 双击 | 不执行 |
| 三指 · 轻触 · 单击 | 不执行 |
| 三指 · 轻触 · 双击 | 关闭当前窗口 |
| 两指 · 按下 · 单击 / 双击 | 不执行 |
| 三指 · 按下 · 单击 / 双击 | 不执行 |

配置自动保存并立即生效，也可点击“恢复默认”。修改配置会取消正在识别或等待判定的手势。同一指数组合同时配置单击和双击时，单击等待系统双击间隔结束后执行；若第二次轻点已开始则等待抬指，双击只执行双击动作。仅启用单击时，抬指后立即执行。

轻触指接触后抬指，无需按压；按下指产生触控板点击反馈后松开，可保持手指接触连续按两次。旧版配置保留在对应轻触项，新增按下项默认不执行。识别按下后会取消这次接触的轻触动作。轻触双击时，两指或三指同时轻点、抬起，然后在系统双击间隔内再轻点一次。每次接触不超过 250ms，各指落下时间差不超过 100ms，每指移动不超过触控板表面的 3.5%。两次轻点须在同一块触控板、相近位置完成。滚动、滑动、长按、四指触摸会打断识别。按下动作每次点击也须在 250ms 内松开，期间不可滑动。切换前台应用、睡眠、锁屏及暂停会清空待识别手势。

关闭的是最前面应用的焦点窗口（无焦点时尝试主窗口），与鼠标所在位置无关。通过 Accessibility 点击该窗口的红色关闭按钮，保留应用原有的未保存提示；有附属对话框或无可用关闭按钮时不执行。“关闭当前窗口”不会发送 Command-W。选择“关闭标签页或窗口（⌘W）”时，会向当前应用发送 Command-W，由应用处理关闭行为：浏览器通常关闭活动标签页，微信等应用关闭当前窗口。此动作不再限制浏览器，旧版标签页动作配置自动沿用。

## 排查

触控板接入或断开（包括唤醒后重新连接）时，TapTap 会自动更新设备监听并清空待识别手势。短时间内的多次设备变化会合并处理；没有连接触控板时仍等待设备接入。手动暂停后不会因设备接入而自动启用。

- 菜单一直提示权限：在系统设置的隐私权限中启用 TapTap 的辅助功能权限。macOS 版本不同，权限名称可能不同。
- 已授权但没有反应：看菜单中的“触摸事件”和“已识别”计数。退出重启后再试。事件一直为 0 表示该系统未向监听器提供触摸帧，需要针对系统版本进一步排查；本项目不声称已完成所有系统及硬件的实机验证。
- 2026-10-29 修复：CGEvent 和 NSEvent 的类型编号不能混用。旧版误订阅 CG 类型 30，并把普通抬指误当作放大手势取消双击，表现为有接触帧但已识别始终为 0。现只通过 CG 类型 29 接收并转换原生手势；真实三指双击样本已加入回归测试。
- 提示输入监控权限：辅助功能用于执行关闭动作，被动输入监听可能还需要输入监控权限。按菜单中对应的授权入口操作，不要反复切换辅助功能开关。
- 提示输入处理积压、监听停用或启动失败：应用会自动暂停，不会每 3 秒重试。处理提示后，在菜单中手动勾选“启用手势”。设置页可查看压力事件、按下次数，区分原始触点正常但压力事件未到达的情况。
- 两指轻点可能同时触发系统右键菜单；程序不屏蔽系统事件，启用两指配置时请留意系统“辅助点按”设置。
- 触发了系统查找：在系统设置 → 触控板 → 光标与点按中，更改“查询与数据检测器”的三指轻点设置。本程序保留系统事件，不屏蔽其他手势。
- 重建后权限失效：本地构建默认临时签名，重新构建可能需要在权限列表移除并重新添加。可设置 `CODE_SIGN_IDENTITY` 为自己的签名身份构建。
- 开机启动失败：先将 App 移到“应用程序”，再通过菜单启用；若系统要求批准，在登录项设置中确认。

## 实现与验证

通过动态加载的私有 `MultitouchSupport.framework` 读取原始接触帧。轻触只依赖接触、离开、时长和位移，无需按压。按下优先使用 `NSEvent.pressure` 的 `stage`：从 0 进入正值开始，回到 0 或抬指结束；1 → 2 → 1 的用力变化仍算同一次按下，不产生额外点击。对于不声明支持压力事件的旧式设备，使用接触期间的鼠标 down/up 兼容识别；抬指后系统补发的轻点鼠标事件会被忽略。公开压力事件无法与私有触点设备直接匹配，多块触控板同时接触时跳过有歧义的按下动作。

CoreGraphics session event tap 使用 `.listenOnly`，不拦截或修改系统输入。输入回调只提取数据并投递同一个有序队列，最多缓存 256 项；不合并或丢弃接触/离开边沿。超限后丢弃待处理流、报告错误并暂停，避免继续使用不完整手势。主线程批量消费数据；输入回调中不调用辅助功能、不停止设备、不重新启用监听。停止时先关闭输入交接、移除 tap，再注销设备回调并停止设备；失败后必须手动重新启用。关闭动作异步在输入回调之外执行。每 3 秒检查权限，失败状态不会因此循环启动。

没有读取键盘、屏幕或网络（标签页动作只发送关闭快捷键）。私有接口没有系统兼容承诺，目前使用 96 字节接触记录并验证状态和坐标，格式不兼容时会停止识别并显示错误。触摸数据只在内存中用于判定手势，不记录到磁盘。设置页底部实时显示权限、触控板数量、接触帧、压力事件、当前手指数、按下次数、识别次数和最近动作结果。

```sh
swift test
```

测试覆盖八种组合及旧配置兼容、无压力轻触、保持接触连续按两次、压力阶段抖动与用力按下、压力早于触点到达、抬指早于压力归零、旧设备点击与系统轻点来点按、单击延迟、双击抑制单击、移动/长按/第四指/滚动取消、队列顺序/溢出/关闭重开。常规测试只回放模拟输入，不注册真实设备；真实设备启停测试需显式设置 `TAPTAP_LIVE_INPUT_TESTS=1`。自动测试通过不代表已经完成实机手势和系统稳定性验证。
